WorldClaw is not a paper-only demo shell. It is a working local control plane that structures target configuration, training orchestration, WorldArena evaluation, ACWM diagnosis, patch planning, loop control, and experiment memory into one reusable workflow.

What WorldClaw Actually Tries to Do

Instead of leaving world-model research scattered across ad hoc scripts, manual notes, and one-off evaluation exports, WorldClaw makes the train-eval-repair path explicit. It keeps the structure of each iteration visible enough that a human or an agent can inspect, compare, and patch it.

01

Unified Train Control

Targets, experiments, stage plans, lineages, bundles, ledgers, and structured summaries all live in one CLI-first layer instead of being spread across project-specific shell glue.

02

Diagnosis-First Evaluation

WorldArena handles benchmark-oriented evaluation, while ACWM Bench adds structure audits, action sensitivity, domain constraints, long-horizon checks, and patch-plan generation.

03

Closed Research Loop

A loop controller resolves training outputs into evaluation inputs, reads back failure modes and patch plans, and turns isolated runs into reusable iteration history.

WorldClaw Pipeline

01

Resolve target and experiment

Merge target config, experiment profile, overrides, and runtime bindings into a single concrete plan.

02

Train or export candidate results

Execute stage-wise training or replay, then emit structured results and artifact registries.

03

Resolve ACWM-ready contracts

Build `train-result.json`, `rollout-manifest.json`, `action-manifest.json`, references, and metric bundles.

04

Run evaluation and diagnosis

Dispatch WorldArena or ACWM, then collect summary, diagnosis, oracles, and patch-plan outputs.

05

Feed back into the loop

Decide whether to continue, converge, block, or request attention, while preserving loop and memory records.

What the Evaluation Layer Is Optimizing For

ACWM is not just video scoring

The ACWM path is explicitly built to inspect whether actions bind to generated rollouts, whether long-horizon trajectories stay stable, whether domain rules are violated, and whether evaluation can return actionable repair plans.

Action-conditioned behavior Checks whether changing actions actually changes generated outcomes in meaningful ways.
Long-horizon stability Tracks rollout drift, visual decay, and structural horizon compliance before expensive experiments compound errors.
Domain constraints and oracles Uses domain profiles and lightweight oracle checks for robotics, driving, game, and custom settings.

Closed-loop artifacts

The eval layer leaves more than a pass/fail. It creates specific artifacts that the next iteration can consume directly.

`summary.json` The unified summary object for train, eval, and loop reporting.
`diagnosis.json` Failure modes, violated constraints, evidence, and fix suggestions.
`patch-plan.json` Machine-readable repair instructions for the next iteration or for capability-gap remediation.

Interpretation of the layers

The important distinction is that `metabot/` remains available, but the default research path now lives in `skills + tools + configs + runs + tests`.

`skills/` Workflow protocols that tell an agent where to start and how to classify failure modes.
`tools/` Actual execution entry points, kept scriptable and testable instead of buried in notebooks.
`runs/` + `memory/` Persistent outputs that allow comparison, reporting, pruning, and historical learning.

Quick Start Commands

Lightweight setup

Start from the CLI-first control plane, not the heaviest training stack.

python -m pip install -r requirements-lite.txt

Inspect train and eval entries

List the eval surfaces and resolve a concrete target/experiment pair.

python tools/eval/main.py list-entries
python tools/eval/main.py acwm list-suboptions
python tools/train/run.py resolve-run ctrl-world --experiment-id smoke-train-eval --json

Plan a provider-aware loop

Plan one ACWM loop iteration without executing full training.

python tools/loop/run.py plan-acwm \
  ctrl-world \
  smoke-train-eval \
  action-sensitivity \
  --provider-id ctrl-world \
  --preflight-profile smoke \
  --json

Notes on Current Project Status

Practical reality of the current checkout

WorldClaw already has a coherent research-infrastructure shape, but some real integrations are still intentionally between smoke-grade and fully metric-complete operation. In particular, richer ACWM sidecars remain one of the most important next steps for closing the loop on real provider backends. 

Current strengths:
- provider-aware closed-loop scaffolding
- train/eval contract resolution
- ACWM diagnosis and patch-plan path
- experiment memory foundation

Current pressure points:
- metric-rich ACWM exports for real backends
- more provider adapters beyond ctrl-world
- making memory a default end-of-loop sink
- tightening repo-private source and public project-page separation
